# 06 — Let field and aim-neutral science name their behavior

**What to build:** A coherent vocabulary for component fields and aim-neutral
science in which values state what they are, operations state what they do, and
generic modules remain independent of their consumers.

**Blocked by:** 05 — Let shared Python values name their truth.

**Status:** resolved (2026-07-30)

- [ ] Field, surface, component, propagation, proof, task, evidence, study, and
      result-support names follow the Sonnet naming contract.
- [ ] Boolean values state their positive meaning and ambiguous completion,
      availability, freshness, or matching predicates name their subject.
- [ ] Mathematical shorthand is expanded in public production names while
      equations and conventional units remain concise.
- [ ] No scalar/vector type tree, `is_vector` flag, generic workflow layer, or
      storage abstraction is introduced.
- [ ] Generic science and field modules do not import metalens, solver, local
      application, or external example consumers.
- [ ] Serialized field, proof, task, evidence, study, and replay identities
      remain unchanged through explicit mappings.
- [ ] No compatibility aliases remain after the batch lands.
- [ ] Field, generic compiler, result-support, replay, architecture, and static
      type tests pass.
