# 03 — Let material binding return an honest outcome

**What to build:** One application-owned material-binding operation that
establishes an exact binding or returns a typed, honest refusal through the
ordinary brief-to-study path.

**Blocked by:** 02 — Let one Rust conflict keep its meaning until the boundary.

**Status:** resolved (2026-07-30)

- [ ] The operation returns either an established material binding or a typed
      material-binding refusal.
- [ ] Missing registration, missing solver-native material, and uncovered
      wavelength remain three distinct refusal reasons.
- [ ] The local application translates those expected outcomes into the same
      honest waiting study meanings without parsing exception text.
- [ ] Malformed catalogues, invalid read-back, invariant violations, and other
      unexpected defects still raise directly.
- [ ] Project material selection remains separate from qualified solver-native
      verification and wavelength-specific sampling.
- [ ] A successful solver-native binding closes over the exact admitted
      selections, samples, product binding, and task references needed for
      replay.
- [ ] Portable material records retain their existing path and meaning.
- [ ] Application-level `conduct` tests cover all expected refusals, successful
      closure, replay, and direct fault propagation.
- [ ] No generic solver port, material registry framework, exception hierarchy,
      dependency container, or compatibility layer is introduced.
