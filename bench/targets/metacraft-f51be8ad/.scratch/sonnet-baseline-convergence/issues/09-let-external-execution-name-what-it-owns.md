# 09 — Let external execution name what it owns

**What to build:** A coherent solver and workstation vocabulary in which
product discovery, qualification, native execution, evidence gathering, and
host placement each name their own responsibility.

**Blocked by:** 05 — Let shared Python values name their truth.

**Status:** resolved (2026-07-30)

- [ ] Lumerical discovery, qualification, material verification, construction,
      dispatch, session, sweep, evidence, artifact, and reference-surface names
      follow the Sonnet naming contract.
- [ ] Workstation host, demand, lane, process-tree placement, memory, topology,
      and reuse names state their exact behavior.
- [ ] Boolean fields, parameters, and locals express availability, reuse,
      qualification, native execution, and capacity with positive polarity.
- [ ] Exact environment keys, native product strings, capability labels,
      artifact schemas, and serialized evidence remain stable at their
      boundaries.
- [ ] The solver adapter continues to depend on the workstation while the
      workstation imports no solver meaning.
- [ ] Product qualification and scientific material binding remain separate.
- [ ] No caller-supplied worker counts, second placement policy, solver manager,
      generic adapter framework, compatibility alias, or hidden live fallback
      is introduced.
- [ ] Fake-session, qualification, dispatch, sweep, evidence, workstation,
      architecture, and static type tests pass without live solver execution.
