# 05 — Let shared Python values name their truth

**What to build:** One intention-revealing vocabulary across Python's
Authority-facing values, advice, canonical documents, and material ownership,
with durable identities preserved at the boundary.

**Blocked by:** 04 — Let four canonical briefs live outside production.

**Status:** resolved (2026-07-30)

- [ ] Types use precise domain nouns and operations use natural verb phrases
      across Authority-facing, advice, canonical, and material code.
- [ ] Boolean fields, parameters, and local values in the touched production
      scope use clear positive `is`, `has`, `can`, or `should` names.
- [ ] Natural predicate methods remain concise when their domain verb already
      expresses a proposition.
- [ ] Broad or ambiguous owners such as data, info, manager, helper, and utils
      are absent from the touched production vocabulary.
- [ ] The root Authority type and `check`, `view`, `fetch`, and `decide` remain
      unchanged.
- [ ] Renamed Python attributes map explicitly to established serialized keys,
      schema identifiers, references, and exact external names.
- [ ] No compatibility aliases, duplicate names, numbered modules, or
      versioned source names remain.
- [ ] Focused behavioral tests, canonical fixtures, replay tests, static type
      checking, and dependency-direction tests pass.
