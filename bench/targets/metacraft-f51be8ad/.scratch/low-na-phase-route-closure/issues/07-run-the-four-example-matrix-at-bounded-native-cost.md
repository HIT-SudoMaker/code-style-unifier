# 07 — Run the four-example matrix at bounded native cost

**Type:** implementation

**Status:** wontfix

**Superseded by:** [Four-brief delivery ticket 07](../../four-brief-metalens-delivery/issues/07-return-and-replay-the-complete-four-brief-matrix.md).

**Blocked by:** tickets 03, 05, and 06.

## Outcome

Four independent adapted-reproduction briefs form one deterministic regression
matrix. Fake evidence closes the full scientific conduct; optional native
evidence proves Lumerical construction and recovery at a disclosed, bounded
cost.

## What to build

- Publish the Johansen circular propagation, Pi square propagation,
  Khorasaninejad rectangular geometric, and Yang elliptical geometric briefs
  as the four canonical factories in `metacraft_next.examples`. Root example
  scripts consume those factories; they do not redefine brief values.
- Remove the old compact/long-focus factories from the public example
  catalogue after their advice-path assertions have moved to local test
  fixtures. They are compatibility sentinels, not a fifth standard example.
- Run each example through compilation, deterministic fake solver evidence,
  matching, Field formation, focus evaluation, Result admission, authority
  reopen, and replay.
- For propagation, exercise 8-, 12-, and 16-state quantizations independently
  and preserve partial closure honestly: formed sets become Results and
  refused sets remain in each Result's formation record; only all-refused
  formation returns a waiting Study.
- Repair the live qualification helper so its inspection and qualification
  path is reachable.
- Keep exactly two opt-in flags:
  `METACRAFT_RUN_LUMERICAL_SMOKE=1` and
  `METACRAFT_RUN_LUMERICAL_SOLVE=1`.
- Before either opt-in path opens a session, preflight the exact material
  catalogue keys required by that path. Stop with an explicit human action
  when a key is absent; never infer or write the native name.
- Bound the native tracer to at most two candidates per geometry. Solve four
  propagation cells and both `x/y` bases for four geometric cells: twelve
  candidate solves. Count the three one-time execution-qualification fixtures
  too, for a hard ceiling of fifteen direct-engine launches.
- Use automatic workstation lanes and record route, geometry, physical period,
  height, material binding, lane, basis, and work identity in each manifest.

## TDD seam

Make the four-example fake matrix the top-level acceptance test. Add narrow
live tests only after the fake matrix closes and only behind the two flags.

## Acceptance

- All four examples complete deterministic fake conduct and exact authority
  replay.
- Each factory returns a fresh immutable brief whose common aim, objective,
  solver preference, budget, and omissions match the specification exactly.
- Propagation examples retain separate 8-, 12-, and 16-state outcomes with
  cyclic phase matching.
- Geometric examples select one cell from `x/y` evidence and rotate
  analytically.
- Every replayed Result retains an ordered fabrication cell table, stable
  state table, and full aperture identity map with exact source references.
- Live test names, candidate counts, assertions, and manifests agree.
- With flags absent, no native product is inspected, opened, or solved.
- With a required material key absent, no native session opens and the
  missing key is reported exactly.
- Smoke alone may inspect, sample, construct, and read back through hidden
  sessions, but launches no direct-engine solve.
- With live solve enabled, the tracer cannot exceed the declared solve budget
  and does not claim a complete scientific Result.
- Workstation dispatch remains automatic; callers supply no worker count.
- Every direct execution uses one admitted lane of four distinct physical
  cores in one locality cell, no SMT siblings, and a 16-GiB process-tree
  limit; concurrent work never exceeds fresh licence or workstation capacity.
- Focused tests, architecture tests, Pyright, and CSU on touched files pass.

## Do not add

- A fifth example or a long native sweep.
- Duplicate brief constants in root scripts and package factories.
- GUI automation.
- A live Result acceptance threshold copied from a paper.
- Test-only scheduling controls in public science interfaces.
