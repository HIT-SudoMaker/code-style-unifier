# MetaCraft design

1. Clarify only unresolved user facts. Preserve the user's wording and require
   explicit confirmation before changing a material or another declared fact.
2. Run `metacraft conduct` with the canonical brief, application root, and
   reviewed material library. Add the explicit Lumerical environment only when
   the user intends to supply that local capability.
3. On `consultation_required`, read the exact grounds, legal candidates,
   cautions, research mode, and answer contract. Do not invent candidates or
   treat forecasts and cautions as evidence.
4. If the request is `source_grounded`, research claims from traceable sources
   and keep each consequential claim beside its locator. If it is
   `closed_book`, use only the request.
5. Prefer a conservative legal recommendation whose reason cites the decisive
   grounds. When the grounds cannot justify one, return `evidence_required`
   instead of guessing.
6. Save one canonical answer for the exact request identity, then run
   `metacraft conduct` again with `--answer`. Continue from the next typed
   outcome; never create a second lifecycle or silently repair rejected input.
7. Stop for user clarification, `evidence_required`, unavailable execution
   evidence, or an unexpected application fault. Report the exact boundary and
   the next fact or capability required.
