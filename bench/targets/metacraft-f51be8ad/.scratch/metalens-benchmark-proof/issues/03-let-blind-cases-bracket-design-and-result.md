## Comments

### 2026-08-06 — exact-cadence audit

The implementation attempt kept the Yun brief byte-for-byte and called the
public `conduct` seam in a fresh application root. Two bounded observations
located the testability contradiction:

- the concrete production-replay Adapter added by this ticket opens
  `RecordedPeriodicResponse` and `RecordedMaterialResponse` with zero current
  activity and zero Authority permits. With no previously admitted records in
  a create-only root, exact Yun returns `WaitingStudies` after about 2.19 s at
  `material_binding`, with
  `recorded_observation_missing:hydrogenated amorphous silicon`;
- an exploratory recorded observation producer admitted material and periodic
  values without Native or permit work and advanced exact Yun through advice,
  height, periodic transmission, cell library, and phase-set formation. It
  then entered paper-scale aperture/field work. The final exact Yun probe
  exceeded the 300 s hard bound, used about 3.2 GiB peak working set and more
  than 347 CPU seconds, and was explicitly stopped. It formed no
  `CompletedResults`. The observation producer was not retained because
  forming observations from the incoming request is not exact replay.

The public composition currently ends at:

```python
MetalensEvidenceAdapter.open(
    *, authority, runs_directory
) -> tuple[PeriodicResponse, MaterialResponse]
```

Angular-spectrum, vector-angular-spectrum, direct-Debye, focus evaluation,
and Result admission are selected and executed inside conduct. Their binding
documents choose qualified local realizations, but none is a replay port that
can return already admitted field or focus evidence. Replacing those functions
in a test would be monkeypatching scientific execution, not exercising a
public Adapter. Separately manufacturing `CompletedResults` would not prove
the original end-to-end wording. This finding led to the subsequently
approved Option C amendment recorded above.

### Human decision packet

Choose exactly one movement before this ticket returns to an agent:

**A — fund an exact long-running gate.** This option failed the proposed first
bound: exact Yun exceeded 300 s, about 3.2 GiB peak working set, and 347 CPU
seconds without producing `CompletedResults`. Raising those limits would
preserve ADR 0018, but it would create a separately approved performance gate,
not a bounded normal-suite proof. Do not start the other three cases under
this option without a new explicit resource budget.

**B — amend the architecture with one replayable field-realization seam.** Add
the smallest aim-specific read/observe Interface capable of returning exact
admitted aperture-through-focus evidence, and compose it alongside periodic
and material evidence. This may make the endpoint cadence deterministic, but
it violates ADR 0018's frozen root/science ownership and Adapter tuple unless
that new owner, dependency direction, and fault contract are separately
designed and accepted first.

**C — weaken Ticket 03 explicitly.** Prove exact blind cadence only through the
last affordable public stage, and prove Result/comparison contracts separately
with bounded recorded fixtures. This adds no production abstraction and is the
smallest Sonnet movement, but it no longer establishes that
`conduct(case.brief)` itself returns the `3 + 3 + 1 + 1` matrix.

Recommendation: choose C as the smallest honest specification amendment. It
keeps exact cadence and bounded Result-contract evidence visibly separate,
adds no production seam for a test-only variation, and does not misstate the
failed full matrix as complete. Choose B only if replayable field evidence is
also a real application requirement. Do not describe C as satisfying the
current ticket wording until that wording is amended.
