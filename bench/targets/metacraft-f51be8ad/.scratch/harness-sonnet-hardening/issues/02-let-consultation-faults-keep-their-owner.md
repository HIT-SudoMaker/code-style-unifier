# Let consultation faults keep their owner

**Parent map:** [Harness-native Sonnet hardening](../map.md)

**Label:** `wayfinder:grilling`

**Status:** resolved (2026-08-09)

**Blocked by:** none

## Question

What exact error table should govern period and height consultation formation,
answer validation, advice construction, conduct translation, and replay so that
caller-owned invalid answers become `ConsultationAnswerRejected`, while stale
domains, malformed references, impossible ordering, storage conflicts, and
implementation faults continue to raise directly from their owning Modules?

Resolve the smallest catch scopes and stable reasons. The result must make the
two questions rhyme without erasing the height envelope asymmetry or parsing
exception text.

## Resolution

Keep the four public `ConsultationAnswerRejected` reasons exactly as they are,
but make `invalid` reachable only through one typed, aim-owned internal fault.
Do not catch `ValueError` at the metalens composition seam.

The internal fault remains `InvalidMetalensConsultationAnswer`, but its owner
moves beside the period and height answer rules in metalens consultation. It
retains the closed `QuestionKind` as data and is raised only for a structurally
valid `ConsultationAnswer` whose caller-controlled contents fail closure or a
question-owned answer rule. Generic conduct catches that type, not a base
exception and not exception text, and translates it to
`ConsultationAnswerRejected("invalid")`.

Period and height acceptance use the same ordered shape:

1. Form the expected request from the current brief and admitted grounds.
2. Require the supplied internal request to equal that canonical request.
3. Validate the caller answer against the request and apply question-owned
   answer rules inside the sole answer-fault catch.
4. Resolve the already validated candidate and construct advice outside that
   catch.

Steps 1, 2, and 4 are direct-fault regions. Only step 3 may raise
`InvalidMetalensConsultationAnswer`. Period and height therefore rhyme without
pretending that height lacks its propagation-envelope asymmetry.

### Error table

| Stage | Condition | Owner and stable outward result |
| --- | --- | --- |
| Command decode | Missing/unreadable/noncanonical answer document | The command Adapter retains `answer_document_invalid`; no typed answer reached `conduct`. |
| Conduct root opening | An answer is supplied for an absent application root | `ConsultationAnswerRejected("not_required")`. |
| Frontier recall or request formation | Foreign/partial root, malformed Study, missing or duplicate evidence, stale domain, malformed reference, brief mismatch, impossible period-before-height order, or invalid research mode | The Module that detects it raises directly. Representative existing reasons include `period_domain_reference_mismatch`, `height_domain_reference_mismatch`, `phase_envelope_required`, `phase_envelope_reference_mismatch`, `phase_envelope_domain_mismatch`, `phase_envelope_height_coverage_mismatch`, and `geometric_phase_envelope_forbidden`. None becomes an answer rejection. |
| Internal request integrity | The request passed to period or height acceptance is not the request re-formed from current grounds | Direct `period_consultation_request_stale` or `height_consultation_request_stale`. This request is produced by MetaCraft, not by the answer caller. |
| Conduct precheck | The request identity already belongs to retained advice, or an answer is supplied after completed results | `ConsultationAnswerRejected("duplicate")`. Duplicate precedes stale. |
| Conduct precheck | A pending consultation exists but the answer cites another request identity | `ConsultationAnswerRejected("stale")`, before scientific answer validation. |
| Shared answer closure | Unknown candidate or ground, request-identity mismatch, forbidden/surplus/unclosed external claims, or another failure of `validate_consultation_answer` | The question rule raises typed `InvalidMetalensConsultationAnswer`; conduct alone translates it to `ConsultationAnswerRejected("invalid")`. |
| Period answer rule | The caller recommendation cannot satisfy the closed period answer contract | The same typed internal fault, then public `invalid`. The integer-nm/unit properties generated by MetaCraft's own request remain direct request/implementation invariants. |
| Height answer rule | A decisive ground is forecast/caution, or a propagation candidate is wholly ruled out by certified standings | The same typed internal fault, then public `invalid`. Envelope restoration and integrity checks remain outside the catch and direct. |
| Candidate conversion or advice construction | A validated candidate cannot be resolved, a generated recommendation is internally invalid, or `PeriodAdvice`/`HeightAdvice` construction fails | Direct question-owned or implementation fault. These operations consume already validated values and must not blame the caller through a broad catch. |
| Advice admission or frontier replacement | Authority admission/fetch failure, advice-reference mismatch, current-admission conflict, or `consultation_frontier_conflict` | Direct storage, Authority, or concurrency fault. An admitted orphan advice record remains possible as specified by ADR 0021. |
| Conduct after no pending consultation | An otherwise unconsumed answer remains | `ConsultationAnswerRejected("not_required")`. |
| Replay | Retained advice cannot re-form the exact current request, reconstruct a valid answer, or regenerate byte-identical advice | Direct question-owned replay reason from Ticket 01, such as `period_advice_request_stale`, `height_advice_request_stale`, `period_advice_replay_mismatch`, or `height_advice_replay_mismatch`. Never `ConsultationAnswerRejected`. |
| Replay codec | A checkpoint codec adds its existing outer context | It may raise `study_frontier_invalid` only with the direct replay fault chained as its cause; it may not turn the fault into advice absence or a new request. |

Wrong runtime types remain direct faults under the existing error discipline.
The public Python Interface does not attempt to repair an object that could not
have been constructed as a strict `ConsultationAnswer`.

### Smallest catch scopes

- Move height request regeneration and exact request comparison out of its
  current broad `try` block, matching period.
- In both questions, catch only failures from shared answer closure and the
  explicit caller-controlled question rules. Raise the typed internal fault
  from that narrow block.
- Resolve candidates and construct recommendations and advice after that block.
  Do not include `StopIteration`, `TypeError`, advice constructors, domain
  validation, or envelope validation in an answer-fault catch.
- Remove the broad `except ValueError` blocks from
  `accept_metalens_consultation`; let the typed internal answer fault cross that
  seam unchanged.
- Generic conduct catches exactly `InvalidMetalensConsultationAnswer` and owns
  the sole translation to public `invalid`.
- Ticket 01 replay catches that typed fault only within its known period or
  height reconstruction branch and raises the matching direct replay-mismatch
  reason. It does not parse its message.

No provider exception, command error, Authority exception, or replay exception
is added to the typed answer-fault ancestry. One typed fault is sufficient;
period and height do not need parallel exception hierarchies.

### Verification contract

Implementation verification should add or retain Interface-level tests for:

- all four public reasons, including duplicate-before-stale precedence;
- period and height unknown candidate, invented decisive ground, request
  mismatch, external-claim closure, and `EvidenceRequired` behavior;
- height forecast-as-decisive and wholly-ruled-out candidate rejection;
- period and height stale internal requests raising their direct question
  reasons rather than public `invalid`;
- every propagation envelope integrity fault remaining direct when an answer is
  supplied, plus geometric envelope prohibition;
- a non-typed `ValueError` or sentinel implementation fault from advice
  construction crossing metalens and generic conduct unchanged;
- Authority admission mismatch and `consultation_frontier_conflict` remaining
  direct;
- Ticket 01's period/height by Recommendation/EvidenceRequired replay matrix
  proving that no replay failure becomes `ConsultationAnswerRejected`;
- command-level malformed JSON/schema remaining `answer_document_invalid`.

Tests should assert exception types and structured reasons, not inspect chained
exception text. Existing broad-catch tests should be replaced rather than
layered with source-shape tests.

This decision changes no public Interface, canonical schema, scientific
choice, or lifecycle. It enforces the error ownership already stated by
`CONTEXT.md`, `DESIGN.md`, SCIENCE, ADR 0018, and ADR 0021, so no new Research
Record, glossary term, or ADR is warranted.
