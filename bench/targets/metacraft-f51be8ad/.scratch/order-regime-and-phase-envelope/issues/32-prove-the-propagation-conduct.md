# 32 — Prove the propagation conduct

**Type:** implementation (spec phase 5)

**Status:** wontfix

**Superseded by:** [Metalens Sonnet convergence tickets 08–10](../../metalens-sonnet-convergence/spec.md#tickets).

**Blocked by:** tickets 23 and 31.

**What to build:** Prove one standard low-na propagation brief through the
public application operation:

`brief -> study -> evidence -> height choice -> cell library -> phase sets
-> aperture -> focus -> result`

The test must expose each admitted fact and recompile from the Authority
view. It must not introduce an end-to-end workflow object or let one
application file interpret every scientific document. Automatic dispatch
uses the qualified workstation lanes; caller-supplied worker counts remain
absent. A live run may return either an admitted result or an honest,
scientifically typed unfinished study, but it may not hide a refusal,
substitute a period, or manufacture a phase set.

**Acceptance:**

- Fast segmented tests cover compilation, qualification, planning, envelope,
  advice, height choice, independent 8/12/16 phase sets, aperture formation,
  and the `0.8f` to `1.2f` focus evaluation.
- One integration test traverses the same public seams with fake external
  boundaries and proves ledger replay after restart.
- One separately marked Lumerical live test uses the standard circular brief,
  automatic lane dispatch, the physical period, and the run manifest.
- The report distinguishes delivered and refused quantizations and records
  the exact evidence behind either outcome.
- Rust source and protocol bytes remain untouched.
- Touched files leave `csu check` with zero hard violations.
