evidence. Any later sweep or field calculation requires a fresh bounded

- [ ] A human explicitly approves the Adviser, Lumerical smoke, solver sweep,
      and delivery flags before any live work begins.
- [ ] Read-only inspection confirms isolated secret configuration, expected
      Lumerical 25v2 identity, valid licence observation, artifact root, and
      clean implementation state without printing or copying secrets.
- [ ] Material smoke opens only after one complete atom/substrate pair is
      registered in the project material library; it never runs with a single
      material or a guessed native name.
- [ ] One bounded solver smoke proves only the response capability it actually
      observes and records product, licence, lane, session, and artifact facts.
- [ ] A human reviews the smoke artifacts before any canonical sweep opens.
- [ ] Each canonical case opens only after its own complete atom/substrate pair
      is registered and verified; missing materials for a sibling case do not
      block a ready case.
- [ ] Real sweeps use observed licence and workstation capacity, one reusable
      hidden session per admitted lane, four physical non-SMT cores, local
      memory placement, and the established lane memory bound.
- [ ] The Yun and Yang cases are run first in bounded stages; the Arbabi and
      Khorasaninejad cases proceed only after their required response and field
      qualifications are present.
- [ ] Every case returns either its real complete results or one exact honest
      waiting reason with all completed artifacts retained.
- [ ] No source, threshold, brief, paper fact, scientific policy, Rust code, or
      solver template is edited inside the live gate.
- [ ] Any defect stops the affected stage, preserves the scene, opens one
      focused implementation ticket, and returns this ticket to blocked.
- [ ] Any genuine scientific or product limitation is recorded as a result or
      caution rather than repaired by policy drift.
- [ ] Final replay runs with Adviser, Lumerical, and Torch execution disabled
      and restores the same admitted studies and results.
- [ ] The delivery report records wall time, solver version, licence
      observation, lane and session counts, candidate and solve counts,
      qualified responses, field realizations, artifact roots, result
      identities, comparisons, cautions, and replay outcome without secrets.
