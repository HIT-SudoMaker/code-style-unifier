This ticket preserves the current exact single-CZT behavior behind the deeper
private seam. Ticket 05 alone replaces that binding and Implementation with the
joint FFT/CZT contract, so no ticket consumes a contract that does not yet
exist.

Rename the current claim/method/capability/schema language from generic
`ideal_field` / `form_ideal_field` / `aplanatic_focus_evaluation` to intention-
revealing aplanatic-reference language across compiler relationship, Study,
evidence, Result and active tests. Replace the old road completely: no alias,
dual task name, forwarding wrapper, schema migration branch, public factory,
registry, or algorithm selector. Keep low-level FFT/CZT realization Modules
separate; this ticket deepens their scientific composition rather than merging
their equations.

Before renaming persisted claim, task, capability and schema identities, freeze
their fixed-point documents and Result references. The cutover is intentionally
one-way: historical application roots remain preserved as stored evidence but
are not current-schema resumable through compatibility aliases or migration
branches.
