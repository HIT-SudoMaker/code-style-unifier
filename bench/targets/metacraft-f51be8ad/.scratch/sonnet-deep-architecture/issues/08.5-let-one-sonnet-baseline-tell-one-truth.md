# 08.5 - Let one Sonnet baseline tell one truth

Type: implementation

Status: resolved (2026-08-04)

Blocked by:

- [Let Field export only shared language](08-let-field-export-only-shared-language.md)

Consumes, but does not wait to re-prove:

- [Let periodic response hide product work](06-let-periodic-response-hide-product-work.md)
  deterministic handoff.

## Outcome

Perform one bounded deterministic cutover that makes the implementation,
domain language, accepted ADRs, current specification, examples, and tests
tell the same architectural truth before the remaining Native gate.

This ticket moves through four ordered movements:

1. scientific choice functions return typed Findings;
2. modules, files, and symbols state their present intent;
3. the four external values become benchmark cases and production loses all
   published-comparison meaning;
4. canonical documentation and Interface tests close the new baseline.

Completing this ticket makes the architecture **Sonnet-ready**. It does not
run Lumerical, close Ticket 06's Native acceptance, produce a receipt, execute
all four benchmark cases, seal the architecture, or create a commit.

## Decision basis

Implement [ADR 0018](../../../docs/adr/0018-let-one-sonnet-baseline-tell-one-truth.md).
A separate Research Record is not applicable because this ticket changes
internal ownership, dependency direction, and naming; it introduces no
external scientific fact.

## Scope

### Movement 1 - Let scientific choices return their meaning

Expose the owning metalens operations as:

```python
resolve_period_choice(...) -> PeriodChoice | Finding
derive_height_domain(...) -> HeightDomain | Finding
resolve_height_choice(...) -> HeightChoice | Finding
```

The return contract is exact:

| Situation | Outcome |
| --- | --- |
| explicit period or height violates a physical constraint | `FindingKind.REFUSAL` |
| advice is missing, unavailable, invalid, outside its domain, or ruled out | `FindingKind.ADVICE` |
| valid exact input selects one value | `PeriodChoice` or `HeightChoice` |
| stale brief identity, domain reference, or grounds reference | direct fault |
| malformed document, wrong runtime type, impossible order, or internal invariant failure | direct fault |

`derive_height_domain` returns a refusal Finding only for an explicit physical
constraint that makes the domain impossible. It raises for malformed or stale
inputs. The Finding's `claim`, `kind`, `needs`, and record references are
complete at this seam; callers do not rebuild or reclassify it.

Delete:

- `diagnose_period_advice`;
- `choose_constrained_height`;
- every `str(error)`, prefix, or exact exception-message branch used by
  metalens conduct to classify period or height choice;
- duplicated compiler validation of a received advice document that belongs
  to the choice operation.

The compiler handles only absent advice and the typed `AdviceStatus` values it
must expose before a choice can be attempted. Conduct admits returned choices
or returned Findings without interpreting their text.

Narrow the adviser Adapter:

- missing configuration and an explicit transport timeout produce
  `AdviceStatus.UNAVAILABLE`;
- received invalid JSON or a scientifically invalid payload produces
  `AdviceStatus.INVALID`;
- malformed provider envelopes, parser defects, unexpected exceptions, and
  contract mismatches raise directly;
- remove the broad `except Exception` unavailable conversion and error-prefix
  parsing.

Do not change cleanup aggregation whose explicit purpose is to preserve both a
primary fault and a cleanup fault.


The examples remain outside the wheel and depend only on the installed root

## Stop and report

Stop and report if:

- a production change would widen the installed root or Authority Interface;
- a second lifecycle, mutable progress store, workspace authority, or error
  framework appears necessary;
- a generic solver, benchmark, consultation, plugin, registry, dependency-
  injection, or naming framework is proposed;
- a compatibility alias, migration, or old-schema reader appears necessary;
- a Finding cannot carry an expected outcome without hiding a structural
  defect;
- a retained Module fails the deletion test and no real policy would return
  to callers;
- benchmark comparison would require published truth inside production;
- a Native solve, failed-workspace reuse, Rust edit, or unrelated-worktree
  cleanup appears necessary;
- deterministic evidence fails after the owning movement is repaired.

Do not reopen this ticket merely because a different name or abstraction also
looks reasonable. After every acceptance item passes, further architecture
work requires one concrete ADR, Interface, dependency, state, error, domain,
test, or Native contradiction.
