## Outcome

Retain actual rectilinear Native reference-surface coordinates as a first-
class periodic observation, then form one complete compatible batch into the
existing uniform `Field` language through one independently qualified Python
numerical realization.

Delete the no-solve `PeriodicReferenceSurfaceRequest` round trip. Keep
`periodic_reference_surface_response` as the independent capability proving
that transmission or polarization work embeds the exact surface from that
same Native solve.

No Native run, application root, commit, Rust change, public-root expansion,
NUFFT implementation, or unqualified numerical fallback belongs to this
ticket.

Raw rectilinear admission and deletion of the shallow request path remain the
first implementation cut. The numerical formation gate below is now frozen,
so the bounded formation cut may follow. This status authorizes deterministic
implementation only; the ticket must not be reported as completed before its
acceptance gates pass.

## Exact Interface and owners

`metacraft.field.__all__` remains byte-for-byte the existing six names.

`src/metacraft/field/rectilinear.py` owns:

```python
@dataclass(frozen=True, slots=True, eq=False)
class RectilinearPlane:
    position_m: float
    horizontal_coordinates_m: NDArray[numpy.float64]
    vertical_coordinates_m: NDArray[numpy.float64]
```

It owns finite immutable `float64` coordinate copies, one-dimensional shape,
minimum length, strict increase, exact equality without NumPy ambiguous truth,
and no uniformity assertion.

`science/periodic_response.py` retains
`PeriodicReferenceSurfaceObservation` as the periodic-response observation
owner. Its `surface` becomes `RectilinearPlane`; it continues to own requested
input basis, output basis, order regime, medium, frame, wavelength, incident
reference power, transmitted power, and finite components. Component arrays
have shape `(len(vertical_coordinates_m), len(horizontal_coordinates_m))`.

`src/metacraft/field/reference_surface_formation.py` owns:

```python
@dataclass(frozen=True, slots=True)
class ReferenceSurfaceFormationInput:
    wavelength_m: float
    surface: RectilinearPlane
    frame: CoordinateFrame
    medium: Medium
    basis: ComponentBasis
    electric_components: tuple[FieldComponent, ...]
    source_references: tuple[Reference, ...]
    incident_reference_power: float

@dataclass(frozen=True, slots=True)
class UniformReferenceSurfaceFormation:
    realization_identity: str
    qualification_reference: Reference

def form_uniform_reference_surfaces(
    observations: tuple[ReferenceSurfaceFormationInput, ...],
    formation: UniformReferenceSurfaceFormation,
) -> tuple[Field, ...]: ...
```

This is one batch operation, not a per-item helper. It preserves input order,
returns exactly one `Field` per input, and returns no partial batch.

`science/metalens/reference_surface_evidence.py` translates the embedded
surfaces and their admitted body references into one formation batch, calls
`form_uniform_reference_surfaces` exactly once, and admits the ordered
`ReferenceSurfaceResponse` documents. It owns no interpolation loop or target-
grid policy.

The all-or-nothing boundary is the complete preflight and returned `Field`
tuple: formation finishes before any admission callback. The subsequent
ordered Authority admissions are content-addressed, append-only, and
idempotent rather than transactional. An admission fault returns no apparent
surface batch; exact facts admitted before that fault remain reusable on retry.

## Deletion decision

Delete from `science/periodic_response.py` and both PeriodicResponse Adapters:

- `ReferenceSurfaceWork`;
- `PeriodicReferenceSurfaceRequest` and its union branch;
- `ObservedPeriodicReferenceSurface`;
- `AdmittedPeriodicReferenceSurface`;
- `_admit_periodic_reference_surface` and dedicated request/response codecs.

Delete `plan_reference_surface_request`. Transmission and polarization
observations remain the one same-solve carriers. Recorded recovery restores
those observations and repeats no solve.

Deleting the new formation Module must make common-grid derivation, periodic
seam handling, interpolation, qualification validation, and provenance
reappear in more than one caller. If deletion removes only a pass-through
function, stop: the Module is too shallow.

## Raw observation invariants

- position is finite;
- each coordinate vector is immutable, C-contiguous, `float64`, finite,
  one-dimensional, length at least two, and strictly increasing;
- grid shape may be non-square and coordinate intervals may vary by axis and
  position;
- component names exactly match the declared basis;
- every complex component is immutable, C-contiguous, `complex128`, finite,
  and matches the rectilinear shape;
- frame, medium, wavelength, requested basis, order regime, power, source, and
  construction context remain exact;
- the Adapter neither reconstructs coordinates nor tests FFT applicability.

The known 43 by 43 uniform qualification observation and 36 by 33 strictly
monotonic non-uniform closed candidate observation must both decode as valid
raw observations.

## Frozen batch numerical contract

The approved realization is `periodic_rectilinear_bilinear_v1`:

1. one 24 by 24 half-open uniform target grid for the whole compatible batch;
2. separable periodic bilinear interpolation;
3. the closed raw terminal seam is represented once on the half-open target;
4. no extrapolation and no amplitude or power normalization;
5. at most 256 surfaces per batch;
6. raw round-trip relative L2 error at most `0.0081`;
7. normalized maximum error at most `0.0093`;
8. relative power-proxy change from a 20 by 20 convergence grid to the 24 by
   24 target grid at most `0.0006`.

The batch requires matching wavelength, physical period, transmission plane,
frame, medium, output basis, and assembly context. Paired geometric inputs
must contain exactly one x-linear and one y-linear observation for each cell.
Different valid Native coordinate grids are permitted; every output field in
the batch uses the one derived target grid.

The formation fails directly when any limit or structural rule is violated.
Callers cannot change this contract or select a fallback.

## Comments

### 2026-08-05 — numerical gate accepted

The numerical study opened the existing failed gate root's retained
`after.fsp` files read-only. It spent zero Native solves and did not reuse,
resume, or mutate the root. Both from-x and from-y inputs had a 400 nm period,
a closed 36 by 33 grid, exact periodic seam agreement, x steps from 10.476 nm
to 15 nm, and y steps from 10.577 nm to 14.711 nm.

Measured diagnostics, in contract order, were:

- from-x: `0.00798322`, `0.00926499`, `0.000571006`;
- from-y: `0.00789876`, `0.00811822`, `0.000236897`.

All values pass the frozen thresholds. This comment removes the numerical
information blocker; it does not claim implementation completion.

The earlier 64 by 64 candidate crossed the already qualified 1 GiB vector-
field guard during high-NA delivery and therefore did not close system
resources. At 400 nm period the 24 by 24 half-open step is 16.67 nm, comparable
to the retained Native maximum step of 15 nm. All five delivery tests across
the four cases passed with the final 24 by 24 contract.

## Error contract

Malformed observation faults are distinct from formation faults:

- `rectilinear_surface_position_invalid`;
- `rectilinear_surface_coordinates_invalid`;
- `rectilinear_surface_coordinates_not_increasing`;
- `rectilinear_component_shape_mismatch`;
- `periodic_reference_surface_observation_invalid`;
- `reference_surface_formation_batch_mismatch`;
- `reference_surface_formation_periodic_seam_mismatch`;
- `reference_surface_formation_extrapolation_required`;
- `reference_surface_formation_unqualified`;
- `reference_surface_formation_numerical_contract_failed`.

No caller parses these strings. Expected absence continues through the
existing typed response outcome; malformed data, unqualified formation, and
numerical-contract failure are direct faults.

## Stop and report

Stop without implementation completion if:

- implementation cannot satisfy the frozen density, batch bound, or
  diagnostic tolerances;
- the candidate requires extrapolation;
- one common batch grid would erase a declared physical context;
- qualification would be inferred from the Lumerical capability;
- a partial batch would need to be returned;
- `Field`, `PlaneSurface`, `metacraft.field.__all__`, Rust, or propagation must
  be widened;
- a Native run or application-root mutation would be required.

## Do not add

- NUFFT, an anisotropic-spacing Field, or non-rectilinear point clouds;
- an algorithm, density, or fallback selector at a caller Interface;
- a strategy Protocol, registry, plugin, compatibility alias, or second
  response lifecycle;
- interpolation in `session.py`, the Lumerical Adapter, or metalens evidence;
- an independent reference-surface request or additional Native solve;
- ticket numbers in production names.
