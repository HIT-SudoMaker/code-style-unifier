# Map — Authority and science Sonnet closure

**Label:** `wayfinder:map`

## Destination

One reviewed implementation specification that hardens the authority core
first, then closes the remaining Python seams as one ordered convergence:

`authority exact -> view clear -> method bound -> propagation branches whole
-> native names true -> qualification one -> dispatch deep -> storage shared
-> architecture closed`

The destination is reached when the Rust contract has an independent,
distribution-safe freeze gate; Python callers no longer interpret raw
authority mappings; scientific methods cannot disappear into an empty
advance; propagation branches replay together; and the Lumerical and field
implementations each hide one coherent body of work behind a small interface.

**Way clear (2026-07-28):** the owner accepted the complete sequence and its
trade-offs. [spec.md](spec.md) and tickets 01–09 are the implementation road.

**Road completed (2026-07-29):** tickets 01–09 were implemented. The remaining
performance, exactness, and live-delivery work continues in
[Sonnet performance and reliability convergence](../sonnet-performance-and-reliability/spec.md).

## Notes

**Domain:** MetaCraft authority and low-na metalens science. Propagation phase
and geometric phase share the metalens lifecycle but retain different
scientific evidence and assignment semantics.

**Normative sources:** `CONTEXT.md`, ADR 0001, ADR 0002, ADR 0003, ADR 0004,
ADR 0006, ADR 0009, ADR 0010, and ADR 0011.

**Research record:** not applicable. This effort corrects implementation
structure and replay behavior found by repository audit; it introduces no new
external scientific claim.

**Standing constraints:**

- Rust remains generic authority. It owns no brief, phase, solver, material,
  numerical method, or scientific result.
- The Rust interface remains one `Authority` with `check`, `view`, `fetch`,
  and `decide`.
- Rust is inspected first. Production Rust changes only for a demonstrated
  authority, integrity, protocol, security, or measured scaling defect.
- Python adapts to Rust. Rust never adapts to a Python convenience.
- `8`, `12`, and `16` identify propagation-phase quantizations only.
- Geometric phase uses one admitted anisotropic cell and continuous analytic
  orientations. A later, explicitly declared fabrication grid may constrain
  those orientations, but geometric phase does not inherit a phase-set
  obligation.
- One implementation wave is divided into small, sequential tickets. Focused
  tests guard each seam; the complete non-live suite runs once at closure.
- The four canonical live briefs remain a later human-enabled delivery gate.

## Decisions so far

- **Rust goes first** `(charted)` — audit the contract, exercise replay at
  scale, classify faults, replace the Git-dependent freeze check, and pass the
  Rust gate before Python changes begin. A clean audit may leave production
  Rust source unchanged.
- **The authority contract stays narrow** `(charted)` — one class, four verbs,
  canonical bytes, generic findings, and no science.
- **Python receives typed authority values** `(charted)` — `Current`,
  `AdmittedDecision`, and `Permit` replace raw mappings after the authority
  Adapter seam.
- **Every compiled method has one local operation** `(charted)` — the
  compiler-to-application relationship is exhaustive. An unbound method is an
  explicit implementation fault, never an honest waiting study.
- **Propagation branches travel together** `(charted)` — all phase-set
  branches produced by one advance are recorded in one immutable checkpoint
  and recalled together in canonical order. The same checkpoint retains the
  complete delivered/refused formation report without turning a refusal into
  a branch. No mutable progress database and no old-checkpoint compatibility
  reader are added.
- **Quantization follows mechanism** `(charted)` — propagation phase may form
  independent 8-, 12-, and 16-state results; geometric phase forms one
  continuous-orientation result and is outside that branch set.
- **Lumerical owns its dialect** `(charted)` — public natural names translate
  through an exhaustive, object-specific, bidirectional product dialect.
  Unknown properties fail before the native engine.
- **Qualification walks once** `(charted)` —
  `configured -> found -> versioned -> licensed -> qualified -> available`.
  The first four stages construct no geometry; `qualified` is the first
  minimal native construction. Production, fake, and live checks cross the
  same interface.
- **Dispatch contains one work life** `(charted)` — science asks to
  `gather_periodic_transmission` or `gather_jones_library`; candidate, lane,
  session, permit, artifact, receipt, and recovery remain internal to the
  Lumerical Adapter.
- **Fields share storage, not meaning** `(charted)` — `Field` and
  `FocalRegion` share one private binary-storage implementation while keeping
  distinct scientific values, schemas, and manifests.
- **Expected seam failures are typed** `(charted)` — only errors that callers
  must classify across a real seam receive types. Local invariant and input
  failures remain direct `ValueError` facts.

## Out of scope

- changing the Rust public interface or moving science into Rust;
- a common solver interface before a second real solver Adapter exists;
- CST, COMSOL, GUI, RCWA, or another solver implementation;
- large-na propagation, Debye–Wolf recovery, optimization, or achromatic
  execution;
- geometric-phase orientation quantization as a new implemented method;
- mutable workflow state, mutable branch progress, or a checkpoint database;
- compatibility readers for the retired checkpoint shape;
- running the four canonical live briefs;
- repository-wide renaming or CSU cleanup outside touched files.
