# Science

Python compiles scientific intent; it does not select a prewritten workflow.

## Meaning

The scientific order is semantic, not a package hierarchy:

- a brief preserves facts;
- advice proposes possibilities;
- a design resolves an aim and objectives;
- a study carries the route and proof;
- a task carries a late binding;
- evidence records an observation;
- a result concludes from complete evidence.

The public scientific language is `brief → study → result`. Aim and objectives
belong to the brief; route and proof belong to the study. Inside the compiler,
a claim states what must be established and a method states how prerequisite
claims and evidence may establish it. This composition refines
`design → study → task`; it does not create a second workflow.

## Brief

A brief retains the user's wording unchanged. Its aim, objectives, operating
conditions, constraints, and preferences are typed without changing their
meaning; absent facts remain absent. Objectives are aim-specific and never
force unrelated fields such as phase, aperture, focus, spectrum, or resonance
into every brief. An external harness may propose an interpretation or
canonical material family, but only explicit user confirmation becomes a
brief fact.

A draft that lacks a fact required to resolve its aim is not compiled into a
fictional route. Compilation raises `BriefIncomplete` with the exact facts to
request from the user. This precedes a study and is distinct from a complete
brief whose proof is honestly waiting on advice, capability, binding, or
evidence; that later incompleteness returns a study with typed findings.

Deterministic brief validation names every absent required fact. The harness
asks those exact user questions and submits only confirmed typed values; there
is no second wording-review or broad design-advice document.

An optional aperture intent records an exact occupied-site count together with
`radius` or `diameter`. It never overrides wavelength, NA, focal length, or the
compiled period. The compiler derives the physical aperture from those optical
facts and rejects a site count whose declared extent does not match.

## Advice

Period and height consultation are closed, provider-free scientific exchanges.
MetaCraft forms exact requests and validates returned answers; it never calls a
model or turns transport availability into a scientific outcome. An external
harness may reason or research, but only the canonical answer crosses into
science.
Metalens science forms each content-addressed request from exact admitted
grounds. A period request follows the brief and `PeriodDomain`; a height request
exists only after the exact `PeriodChoice` has formed an admitted `HeightDomain`.
Propagation height consultation additionally requires the exact admitted
`PhaseEnvelope`, while geometric height consultation forbids one. Each request
carries finite legal candidates, typed grounds, exclusions, cautions, research
mode, and an answer contract. It contains no provider, model, endpoint, harness,
or benchmark truth. A missing answer creates no advice, and a malformed answer
raises before Authority mutation.

The shared consultation values distinguish facts and constraints from forecasts
and cautions. A validated answer cites the exact request and returns either one
legal recommendation with decisive ground identities or one explicit evidence
requirement. Source-grounded answers retain closed external claims with absolute
HTTPS or `doi:` locators; closed-book answers retain none. Validation establishes
shape, identity, and citation closure, not the truth of an external source. Only
fact and constraint grounds may be decisive; forecasts and cautions remain
non-authorizing context.

A document-bearing period or height consultation has one exact identity derived
from its canonical document. Deriving that reference does not claim Authority
admission. Local composition admits the document first, verifies that Authority
returned the same identity, and only then exposes the unchanged advice record
to compilation. Replay begins with the recorded Authority reference and fetches
those exact bytes. Scientific adoption remains separate: only an
`AdvisedPeriod` or `AdvisedHeight` basis says that validated advice became a
choice.

A successful external answer is not a prerequisite for compilation. Missing
facts remain unresolved unless an explicit deterministic policy supplies them;
an evidence requirement creates no period choice and never licenses a guess.

Each consultation owns one bounded scientific choice. Current metalens
consultations choose only period or height; method, realization, material
confirmation, solver binding, and qualification remain in their owning seams.

For a metalens brief without an explicit cell period, the request follows the
exact material sample and admitted period domain. Accepted `PeriodAdvice`
retains only its exact brief and domain identities, request identity, scientific
conclusion, request-owned grounds, and external claims. It has no status,
provider, endpoint, model, prompt, raw response, failure, or synthetic field.
Pure validation either establishes that exact `PeriodChoice` or leaves an
evidence-required finding; it never rounds or substitutes the recommendation.
The choice retains one period basis—brief constraint or exact period advice—and
alone permits the compiler to derive the height domain. Accepted `HeightAdvice`
retains the corresponding provider-free fields plus the exact propagation
envelope reference when one is required. The brief's dimension step is never
an advice field.

Replay first proves that each retained advice document is admitted and that
Authority returns its exact bytes. In fixed period-before-height order it
restores the current domain and, only for propagation phase, the current
envelope; forms a request for every `ResearchMode`; and requires exactly one
identity match. A retained numeric recommendation must reverse-map to exactly
one current nanometre candidate, while `EvidenceRequired` retains its exact
conclusion. Both are reconstructed as a closed answer and pass through the
same period or height acceptance rule used by fresh conduct. A different
regenerated byte is a direct replay mismatch, and replay neither admits a new
record nor reopens consultation.

Both seams expose the same closed request and answer values rather than a
provider callback. `PeriodAdvice` and `HeightAdvice` remain aim-owned schemas,
and generic `Study` restoration stays structurally opaque to both. No generic
choice framework is introduced merely because the two scientific questions
share transport-free value shapes.

Answer rejection is equally narrow for both questions. Each question first
re-forms and compares its exact current request. Only failures of the shared
answer closure or an explicit question-owned answer rule cross the typed
metalens answer seam and become public `invalid`; the fault retains whether
period or height rejected the caller-controlled contents. Request formation,
domain or envelope integrity, candidate conversion, advice construction,
Authority admission, storage, concurrency, and implementation faults remain
direct. Generic conduct is the sole translator of the typed answer fault, and
neither metalens composition nor the command classifies exception text.

A brief that requests generated lateral geometry declares its positive integer
dimension step as a fabrication fact. Deterministic brief validation reports
it when absent. The compiler, height domain, consultation seam, and Adapter
never infer a step from the period. A fixed cited geometry does not manufacture
a meaningless step.

## Period and height

The compiler first derives one period domain from the exact brief, material
binding, wavelength, and physical ceilings. One explicit constraint or exact
advice becomes a deterministically validated period choice. Only then does the
compiler derive one finite height domain from that choice, the aspect limit,
and fabrication grid. Neither domain contains a solver response observation.

The owning seams are typed:

```python
resolve_period_choice(...) -> PeriodChoice | Finding
derive_height_domain(...) -> HeightDomain | Finding
resolve_height_choice(...) -> HeightChoice | Finding
```

An explicit physical violation returns a refusal Finding. Missing or
evidence-required period or height advice returns an advice Finding. Stale
identities or references, invented grounds, illegal candidates, malformed documents, wrong
runtime types, and impossible order raise directly. Compiler and conduct admit
only validated values without classifying exception text.

For the current four-brief delivery, the 532 nm visible brief uses
`500–800 nm` in 50 nm steps. The 940 nm and 1550 nm infrared briefs use
`0.5 × wavelength` through `0.6 × wavelength`, with the lower value rounded
up and the upper value rounded down to 50 nm. Thus the 940 nm brief considers
500 and 550 nm; 1550 nm considers 800, 850, and 900 nm. This is the current
finite prior, not a universal spectral-band definition.

When the brief states an exact height, that value forms a singleton domain
after physical validation, even when it lies outside the selected control
strategy's default
height prior. Its basis is the brief constraint; no synthetic advice is
created. Otherwise the height request presents the exact brief-derived facts,
period choice, fabrication ranges, candidate counts, and cautions. Propagation
requests label model spans as forecasts and certified standings as constraints;
the envelope must cover every legal height exactly once. Geometric requests
state that height alone cannot establish Jones response.
A validated answer recommends exactly one allowed height with one reason, or
states the evidence still required. A pure policy adopts a recommendation only
when it belongs to the domain and leaves the method's necessary candidate count.
Propagation phase requires at least sixteen distinct generated dimensions for
its requested 16-state set;
geometric phase requires at least two distinct axis values for one
anisotropic pair. These are arithmetic necessities, not claims of phase
coverage, conversion, or efficiency. The policy never ranks alternatives,
rounds, repairs, substitutes, or invents a fallback.

The resulting height choice cites the exact domain and one discriminated
basis: brief constraint or exact height advice. Only after that choice is
admitted may Lumerical gather a detailed lateral cell library at the single
chosen height. The current cell-library methods contain no multi-height solver survey; such
a survey would be a future optional experiment, not a prerequisite for height
advice.

## Design

A design resolves the aim, objectives, operating conditions, constraints,
allowed control strategies and capabilities, and budget. It stops before the
compiled route, proof, numerical methods, solver products, local
qualifications, capacity, and task structure.

The shared `Design` carries only aim-neutral facts. Aim-local intent lives
with its aim: `MetalensBrief`, its atom, aperture, and fabrication intent,
`MetalensDesign`, and `ControlStrategy` belong to `science.metalens/`.
`MetalensDesign` retains the exact numerical aperture. It does not duplicate
that value through a derived regime enum or label.

Material or fabrication requirements may constrain a design. Their exact dataset or solver-native binding belongs later.

A route is compiled into the study in one order:

1. `declared` — honor an applicable control strategy explicitly named by the user;
2. `determined` — choose the sole claim–method proof allowed by the declared facts;
3. `proposed` — when several proofs remain applicable, present the advised trade-off for user confirmation.

An inapplicable declared strategy fails with its conflict. No route is silently
substituted, and advice alone cannot settle an ambiguous evidence topology.

## Study

A study is an immutable compilation of one design, admitted evidence, and
registered capabilities. It contains the compiled route, complete proof, the
claims already satisfied, the tasks now ready, and the facts still unresolved.

New admitted evidence produces a new study. The previous study remains unchanged. Identical design, evidence, and capabilities compile to identical study bytes; no sequence number or mutable workflow position participates.

A caution preserves an evidence-backed limitation without interrupting that
order. It neither closes a claim nor blocks a task or result. The compiler
retains it in every later study and therefore in the exact study closure.
A conclusion cites that closure and its evidence instead of copying caution
text into another authority object.

The sampling ceiling is the sole hard metalens period-legality boundary. Its
period limit is the greatest multiple of 10 nm strictly below the exact
sampling ceiling for every current response capability. The material-derived
order ceiling remains exact proof context rather than a candidate filter. A
brief constraint or validated advice may select any 10 nm-aligned period
through the period limit; no downstream Module substitutes a ceiling for that
selected period or silently clamps an invalid proposal.

The selected period is `zeroth order` below the order ceiling and `multi order`
at or above it. Multi-order remains legal and carries an explicit caution, but
coefficient-only field formation refuses to present G0 as the complete output
field. The separately qualified sampled reference-surface route is the only
current route that can retain multi-order into a complete field (ADRs 0009 and
0022).

The design retains intent and the brief-derived sampling ceiling; it does not
carry a provisional optional period. The period domain owns both physical
ceilings, the strict period limit, and applicable fabrication rules. The
period choice owns the validated period and its basis. The height domain cites
that choice and owns only the finite height and lateral candidate domain.

## Claims and methods

An aim declares terminal claims: the scientifically testable statements that
must close before its result may be concluded. A method establishes one claim
from exact prerequisite claims and evidence under explicit applicability
conditions. Claims and methods are typed compiler language, not public
workflow stages or Rust state.

The compiler composes registered methods backwards from terminal claims to
form one complete proof, then closes that proof forwards with admitted
evidence. A route is the selected claim–method graph and the reasons for its
selection. A proof is its complete prerequisite and evidence topology.

Aim modules may resolve aim-specific intent, declare terminal claims, and
interpret a closed proof. They do not choose solver products or own an
end-to-end process. Method modules do not collect briefs, run workers, admit
facts, or return route results. There is no public rule, graph, registry,
plugin, reflection, dynamic-discovery, or AI-planning Interface.

The propagation-phase and geometric-phase routes are two compiled proofs for
the current metalens aim. They share authority, materials, binding machinery,
the evidence composition, phase-circle semantics, the aperture contract, and the
qualified low-na field implementation. Their phase response, polarization,
selection, channel, and acceptance evidence remain distinct and cannot satisfy
one another's claims.

## Tasks

A ready proof need first declares a required capability. A binding then
selects one exact qualified method and realization. Only that fully bound
operation becomes a task: no binding, no task.

Each task fixes its inputs, expected evidence, prerequisite references,
binding, and capacity scope. It carries no mutable status. If no binding is
available, the proof need remains unresolved in the study.

## Evidence execution

Aim composition realizes ready tasks through typed evidence ports. Product
Adapters own qualification, capacity, permits, native execution, observation,
artifacts, and cleanup; they store no mutable scientific progress. A stopped
process may recover an already admitted work receipt only after its permit,
capacity scope, evidence schema, binding, and task identity match the current
ready task. Recovery is product work evidence, not a second public conduct
call or an existing-application-root mode.

A transmission or polarization solve may embed one reference-surface
observation from that same solve. Its horizontal and vertical coordinates are
raw rectilinear scientific facts: finite and strictly increasing, but not
necessarily uniform, square, or equal in count. Product qualification of the
observation capability does not claim that those samples already satisfy a
uniform-grid numerical method.

When downstream field mathematics requires uniform sampling, one Field-owned
batch formation transforms all required rectilinear surfaces onto one common
uniform grid and qualifies that transformation independently in Python. The
batch succeeds completely or yields no Fields. The qualified realization is
`periodic_rectilinear_bilinear_v1`: a common 24 by 24 half-open grid, periodic
bilinear interpolation, at most 256 surfaces, no extrapolation or
normalization, raw round-trip relative L2 at most `0.0081`, normalized maximum
error at most `0.0093`, and 20-to-24 relative power-proxy change at most
`0.0006`. Ticket 08.6's resolved production formation implements this exact
qualified contract.

The 24 by 24 density closes the qualified 1 GiB high-NA vector-field guard;
the earlier 64 by 64 candidate did not. At 400 nm period its 16.67 nm target
step remains comparable to the Native grid's largest 15 nm step, and all five
delivery tests across the four cases pass.

A solver task that fans out over unit-cell candidates extends that identity
with the exact height-choice reference and candidate construction. When one
anisotropic candidate needs two basis observations, each basis further owns a
distinct permit, receipt, artifact path, and observation identity. The
resulting canonical hash, not the human-readable geometry name, owns the
permit. Thus identical dimensions from another brief, material, wavelength,
basis, or compiled task cannot be recovered as this task's evidence. Partial
product recovery executes only the missing identities and restores the
original candidate order before aggregation. Only the validated aggregate
Jones response closes the scientific claim; basis receipts remain
recoverable records, not separate proof obligations.

A task with no external capacity scope belongs only to `local:science`.
`None` never means that an arbitrary solver or product scope may execute it.
The task's qualified method supplies the typed scientific validator. Science
applies that validator before receipt and again when recovering a receipt;
matching a schema label alone never closes a claim.

Every permit ends exactly once. A valid observation, whether it reports
scientific success or failure, is admitted as a receipt. Revoked or expired
work that leaves no valid observation ends with a close. Failure never leaves
a permit open.

## Evidence

Execution produces an observation, not evidence. Python validates its scientific form and proposes it through the authority adapter. It becomes evidence only when Rust admits the proposal.

Rejected or unproposed output remains an observation and closes no claim. The
compiler reads only admitted references from the authority view.

The existing `ProjectExecution` may durably record that a native solve
completed before observation. A later observation failure remains the current
call's unchanged fault; it creates no diagnostic schema, scientific evidence,
receipt, recoverable work, or lifecycle transition.

## Result

A result is concluded only from a complete proof. Scientific evaluation
belongs to the establishing method; conclusion runs no solver, accepts no new
external answer, propagates no field, and recomputes no metric. Its proposed
result cites the exact closure and admitted scientific values.

The result is the sealed public conclusion seam. A conclusion becomes a result
only when Rust admits it. Partial evidence remains reusable input to the next
study, but it is never presented as a partial result.

Current quantized propagation-phase conclusion follows one semantic chain:

`phase set → aperture → field → focal region → focus → result`

A phase set is one explicit 8-, 12-, or 16-state realization. A metalens
`Aperture`
maps occupied sites to stable state identities and carries typed fabrication
cells and optical states. Phase level is optional metadata: a future
pointwise assignment uses the same `Aperture` without it. The evaluator consumes
the realized complex response of each assigned state; it never substitutes an
ideal phase mask.

Each requested propagation quantization answers independently with either a
complete `PhaseSet` or a `QuantizationRefusal`. Candidate shortage and
inadequate cyclic coverage are ordinary scientific refusals, so their stable
reason is returned separately from the requested level count and cell counts.
Only complete phase sets become branches; the formation report retains every
refusal. Malformed libraries and impossible assignments remain direct faults.

One admitted `Cell` is the public fabrication identity shared by response
evidence, selected states, aperture, fabrication output, and result. A planned
candidate and a solver-native construction remain internal values; neither is
a second public Cell. Its typed geometry is `Circle`, `Square`, `Rectangle`,
or `Ellipse`. Jones evidence wraps that same Cell; it does not introduce a
parallel rectangular-fin or elliptical-cell model.

Focus is searched and refined from `0.8f` to `1.2f`. Completion requires the
principal focus and the axial and transverse half-maximum crossings to be
bracketed. Evaluating only the expected focal plane, or reporting an
unbracketed width as complete, is not a scientific result.

An incomplete focus survey remains an immutable diagnostic record. It does
not become focus evidence; the study returns an `incomplete` finding that
cites the record and waits without expanding the requested interval or
attempting Result construction.

External material or periodic-response absence returns an `unavailable`
finding. Conduct retries that typed kind without interpreting its diagnostic
reason. A `refusal` remains a scientific or physical conclusion and is never
made retryable by wording.

## Compilation

The compiler has four internal passes:

`resolve → prove → bind → close`

1. `resolve` preserves the brief and resolves one design from its aim,
   objectives, conditions, constraints, explicit choices, and reviewable
   advice.
2. `prove` expands terminal claims through applicable registered methods into
   one deterministic route and complete proof.
3. `bind` matches only ready proof needs to qualified capabilities, methods,
   realizations, templates, materials, and local facts.
4. `close` validates admitted evidence against exact claims and bindings,
   emits newly ready tasks, or concludes the result from a complete closure.

## Conduct

`conduct(brief, *, application_root, evidence_adapter=None,
consultation_answer=None)` is the single brief-first application entry. It
compiles before filesystem access. An invalid or unsupported brief therefore
creates no root. The first valid call claims one absent application root and
creates exactly:

```text
application root/
    authority/    Authority workspace
    runs/         product artifacts
```

Later calls resume only a structurally complete root bound to byte-identical
brief content. Foreign and partial roots fail without repair. Conduct restores
completed Results or re-derives the next consultation request from the current
`StudyFrontier` before external evidence opens. Missing advice returns
`ConsultationRequired`; exact answer adoption checkpoints one successor under
the per-root execution lock. Invalid, stale, duplicate, and not-required input
raises `ConsultationAnswerRejected` without hiding storage faults.
Supplying an answer for an absent root uses a reopen-only path and is rejected
before any directory is claimed. Authority has no multi-proposal transaction:
if the frontier compare-and-replace unexpectedly fails after its immutable
advice record was admitted, conduct raises `consultation_frontier_conflict`
directly. The current frontier and its evidence do not advance; retry is safe,
although the content-addressed non-current advice record remains in Authority.

An aim-specific `MetalensEvidenceAdapter`, when supplied, opens at most once in
the call and only at a genuinely ready executable-evidence boundary. Absence
means no executable capability and returns honest `WaitingStudies`; it creates
no fake port or state. Repeating a pending request or completed result opens no
product and repeats no scientific work.

Across that one conduct life, each call realizes only ready work, admits validated
evidence, and recompiles immutable Studies until the proof is complete or
honestly waiting. Authority mutation, product execution, and conclusion
admission remain behind the application boundary, so callers cannot compose a
second lifecycle.

Every derived task document is admitted with the exact reference closure
present in that document. The compiled study then binds each evidence reference
to its prerequisite claim, qualified binding, and consultations before result
closure. External observations additionally pass through the route-neutral
product execution life, where Rust owns capacity, permits, receipts, and closure. Pure
deterministic derivation does not pretend to consume solver capacity, but it
still becomes evidence only after Rust admission.

The admitted Study carries one advice sequence. Metalens compilation derives
period- and height-task consultation identities from the matching canonical
advice documents; it does not accept a parallel caller-supplied reference.
Checkpoint writing projects those same derived identities into its established
period and height slots, and reobservation restores records only after
fetching those references from Authority. Ordinary design advice remains
unbound and is never assigned a synthetic Authority identity.

An incomplete call returns its immutable `Study`, including ready tasks and
typed findings; it never guesses a nearby method. A complete proof first admits
the exact brief, design, and study closure, then asks the aim-owned conclusion
rule for conclusions. Each conclusion becomes a public `Result` only
after its aim-owned result type, exact closure, schema, and complete
provenance pass validation and Rust structured admission.

Propagation studies return their 8-, 12-, and 16-state results separately.
Low-na geometric studies return 8-, 12-, and 16-orientation results from one
selected cell and one continuous orientation relation. `conduct` preserves
every delivered result and never selects a winner.

The product execution life executes externally bounded ready tasks, proposes
observations to Rust, and closes every permit. The application reads the
resulting authority view and invokes the same compiler again. These compiler
passes are not workflow positions and are never persisted as mutable status.

The compiler is a pure transformation at its seam: identical admitted inputs produce the same study. Execution availability may block a task, but it must not rewrite the scientific design.

## Low-na field

The metalens aim forms one single-wavelength component `Field` from its
aperture. The shared Field Module prepares that `Field` under the realization
selected by the compiled task, searches one caller-selected axial interval,
and returns one finished aim-neutral observation with its matching propagated
plane. No reusable propagator escapes that call. Metalens owns the interval
and preferred distance, `FocalRegion` assembly, and focus evaluation. A `Field`
records its surface, frame, medium, component basis, electric components, and
exact sources. The brief separately records incident polarization; local
polarization belongs to the field components.

The current qualified realization applies the angular-spectrum operator
componentwise under the declared low-na approximation. It owns sampling,
padding, coordinates, Fourier sign, shifts, normalization, and propagating or
evanescent treatment. Those choices are realization and qualification facts,
not prefixes on Field, Focus, or result types.

This realization has one PyTorch implementation. Local workstation observation
selects CUDA when CUDA is available and Torch CPU only when it is not; the
selected device must then pass qualification. A failed CUDA qualification
leaves the study waiting and never triggers a hidden CPU retry. Selection
occurs once during composition. Execution restores the exact admitted
realization from its task binding rather than observing device availability
again, then moves the same tensor program to that bound device. Complex128
arithmetic, two-times padding, device, and Fourier convention are exact
binding, qualification, and provenance facts.
Qualification exercises the same numerical configuration that execution
records; no NumPy FFT implementation or hidden four-times-padding fallback
remains. NumPy may represent immutable authority arrays and small evaluations
outside the numerical propagation implementation.
Real coordinate and wave-number tensors are explicitly float64 and complex
field tensors are explicitly complex128; the implementation never inherits
Torch's global default dtype.

Numerical provenance names mathematical facts rather than a library:
negative forward exponent, inverse normalization by sample count, discarded
evanescent terms, and two-times padding. Provider-shaped values such as
`numpy_negative_forward` do not survive the migration.

Qualification uses that exact configuration. It verifies zero-distance
reconstruction and an apodized Gaussian propagation and refinement case on the
selected device. It does not preserve the old nonzero-distance finite
plane-wave fixture by secretly changing padding.

The realization prepares one source spectrum per nonzero component and
propagates the requested axial distances in bounded array batches. An
identically zero component remains an explicit zero component without an FFT.
The coarse survey and local refinement may be separate batches, but Python
does not repeat the source FFT or issue one inverse transform call per plane.
Batch sizing is derived from the selected device's observed usable memory and
retains a safety reserve. Because the final aperture grid does not exist at
qualification time, qualification records a safe working-memory budget, not a
plane count. Execution refreshes usable memory, takes no more than that budget,
and derives its actual batch from the real two-times-padded grid and explicit
tensor sizes. It records the realized batch as provenance. This is an internal
implementation fact, never a caller argument or imported constant. If one
plane cannot fit, the study waits; the realization does not change device or
padding.

Metalens evaluation remains strategy-specific. Propagation-phase evidence
establishes focus from its quantized aperture, while geometric-phase evidence
assigns physical handedness components to converted and leakage roles under
its exact incident-polarization convention. They share the aim-neutral
component-field propagation Interface, not scientific meaning.

The public low-na evaluator surveys the realized aperture field across
`0.8f–1.2f`, then refines around the principal focus. It reports expected and
found focus, focal shift, separate x and y half-maximum widths, depth of focus,
transmitted fraction, focused fraction, incident-normalized focus efficiency,
and explicit bracketing status. The focal-region evidence retains only the
axial intensity curve, complex best-focus plane, incident reference power,
transmitted aperture power, binding, and execution provenance. The older
ambiguous `source_power` name and nominal-plane `focus_metrics` helper do not
survive as public completion paths.

The current low-na capability requires `na ≤ 0.5`, a single wavelength, a
declared componentwise aperture approximation, and qualified sampling and
convergence. This threshold is a conservative release gate, not a permanent
physical boundary.

Values above the gate keep their requested numerical aperture and compile to
the pointwise vector route. The compiler never clamps or lowers that value to
enter the low-na route. Unit-cell response remains vector full-wave work, and
finite-aperture evaluation uses the route selected for the admitted range.

The current Lumerical unit cell has one observation object:
`addobject("grating_s_params")`. That analysis group owns its source and
reflection/transmission reference planes. MetaCraft does not add a second
source or standalone field/power monitor beside it. The FDTD region,
substrate, and meta-atom remain ordinary construction objects; mesh policy
belongs to the FDTD region.

The group-owned result returns its actual lateral coordinates. MetaCraft keeps
those coordinates on the same-solve rectilinear observation and does not
reject a valid result merely because successive coordinate differences are
nonuniform. Uniform reference-surface Fields are a later qualified batch
formation, not an Adapter correction or an independent no-solve request.

The physical frame is declared from its bounds. Its lateral spans equal the
unit-cell period; the source lies at `z_min`, the reflection plane lies at
`z_min + reflection_offset`, and the transmission plane lies at
`z_max + transmission_offset`. Both offsets are currently `100 nm`.
Lumerical's native group center and span are adapter details derived from
these physical positions and are verified by reading back the group-owned
objects after setup.

Illumination enters from the substrate side and travels forward along `+z`
toward the meta-atom. The periodic FDTD region uses mesh accuracy `4`. This is
the fixed release default: a live 2025 R2 comparison found only modest runtime
cost over accuracy `2`, while phase stability against the accepted reference-
plane shift improved materially. It is a reproducible engineering default, not
a substitute for a later problem-specific mesh-convergence proof.

Periodic FDTD time follows ADR 0025 rather than one universal duration. The
complete FDTD span, admitted material indices, wavelength, and ordinary-method
guards form one ordinary maximum and one doubled extension. Native
autoshutoff may end either tier early. A second maximum-time stop is accepted
only when the consumed response—and the complete sampled near field when that
capability is present—has converged within the declared numerical tolerances;
otherwise the work is refused. This is bounded numerical closure, not a
caller-selected solver setting or an estimate that one optical transit proves
decay.

## Current slice

The current implemented slice targets `metalens` across low and high
numerical aperture:

- `propagation phase`: adopt one validated period and height choice, gather one fixed-height cell
  library, form separate 8-, 12-, and 16-level phase sets with distinct cells,
  assign stable state identities into one `Aperture`, propagate its realized
  complex field, search `0.8f–1.2f`, and conclude with exact references.
- `geometric phase`: establish the polarization convention, adopt one
  validated period and height choice, gather paired basis evidence for the candidate
  domain, select one anisotropic cell, derive one continuous rotation relation,
  and form separate 8-, 12-, and 16-orientation sets analytically; assign the
  shared state-identity `Aperture`; propagate
  both handedness components; evaluate converted focus and retained leakage;
  and conclude three results with exact references. No orientation-specific
  solver task or nominal-plane result is presented as complete.

Propagation phase and geometric phase share the lifecycle and metalens/Field
Modules, not response evidence. Their phase rules, polarization assumptions,
unit-cell observations, and acceptance criteria remain distinct.

Component and electromagnetic propagation also remain explicitly dual. Their
transverse complex fields agree on the strict adequately sampled linear test
domain, but the current 940 nm / 480 nm benchmark grid exceeds the vector
method's half-wavelength sampling bound. PB Fields additionally own right/left
channels and converted/retained power, whereas vector propagation requires a
transverse-linear input and returns absolute longitudinal Poynting power.
Those are physical Interface differences, not errors that a looser tolerance
or low NA can erase. The parity decision changes no route or binding.

For high NA, pointwise fabrication assignment retains the same-solve raw
rectilinear reference-surface response, its separately qualified uniform
batch formation, vector angular-spectrum field, and joint FFT/CZT Richards--

owns the exact focal coordinates and shared pupil preparation; FFT forms the

`FocalFieldComparison` owns only observed-versus-ideal roles, method bindings,

The vector angular-spectrum Module owns the bounded axial survey behind one

### Propagation-phase proof

The route requires a target phase, exact material, period, and height
evidence, one
fixed-height periodic complex-response library, a traceable 8-, 12-, or
16-level phase set, a state-identity aperture assignment, qualified low-na
field propagation, and a bracketed focal-region result.

Its golden proof relationship is:

`focus ← focal region ← field ← aperture ← phase set ← fixed-height cell library ← periodic complex transmission ← height choice ← height domain ← period choice ← period domain ← material binding`

Phase values are canonical on `[0, 2π)`, `0 ≡ 2π`, and every matching loss
uses cyclic phase distance. The 8-, 12-, and 16-state proofs remain separate.

These are evidence dependencies, not workflow positions. Existing matching
evidence removes work; changed material or fabrication facts invalidate only
the claims whose exact references no longer match. Advice may suggest geometry
ranges or trade-offs, but it cannot supply response, coverage, transmission,
field, or focusing evidence.

### Geometric-phase proof

The route requires an exact polarization convention, material, period, and
height evidence, one anisotropic unit-cell response, one analytic orientation
relation, one 8-, 12-, or 16-orientation set, a traceable state-identity
aperture, a component Field, converted-focus and retained-leakage evaluations,
and a bracketed polarization-aware focus result. The geometric proof closes
only over this exact chain.

Its golden proof relationship is:

`focus ← focal region ← field ← aperture ← orientation set ← analytic orientations ← one anisotropic cell ← Jones response and polarization convention ← height choice ← height domain ← period choice ← period domain ← material binding`

The x and y incident responses have distinct work identities, permits,
receipts, and observations. A candidate becomes complete only after both
responses close under the same binding and construction; interrupted work
reuses the admitted basis and executes only the missing one. After one cell
is selected, orientation states are derived analytically; no
orientation-specific FDTD task exists.

The compiled geometric claims are `orientations` and `orientation_set`, never
a propagation-shaped `phase_set`. The first carries the continuous analytic
law; the second names one ordered fabrication alternative. Equal 8/12/16
counts do not merge their different physics.

An ideal `2θ` rule alone is insufficient. Handedness, time sign, Jones basis, channel order, orientation sign, conversion efficiency, and leakage remain explicit evidence. Propagation-phase response evidence cannot satisfy this proof.

The converted channel owns the bracketed focus result. The retained channel is
propagated independently over the same `0.8f–1.2f` axial samples and reports
traceable leakage power and peak intensity; it does not borrow useful-focus
language or efficiency from the converted channel.

### Selection and optimization

Current methods use deterministic selection only. Quantized propagation phase
selects from a finite qualified library under an explicit loss and tie-break;
geometric phase maps orientation under an exact qualified
Pancharatnam–Berry convention; high-NA routes assign pointwise.

Optimization remains future capability. When a concrete proof need requires
search, an optimizer may become one qualified realization and binding for that
need; it will not become a public workflow layer. The current release contains
no optimizer Module, placeholder, or implementation.

## Materials

Python registers three material sources:

- a user-owned `txt` or `csv` table with explicit units and columns;
- an immutable downloaded dataset from `refractiveindex.info`;
- a solver-native material identity bound to one qualified external solver.

Local-table and refractiveindex.info importers produce the same portable material record. The record retains immutable source bytes, provenance, units, covered band, and canonical optical data; validation and interpolation are shared.

A material sample resolves one requested wavelength or band from one material
record under an explicit interpolation policy. A changed wavelength or policy
produces a new sample; the record remains unchanged. Sampling never
extrapolates beyond the covered band.

A solver-native material never becomes a portable material record. The project
material library instead retains one explicit solver material for each selected
solver and canonical material family. When a `material_binding` task is ready,
the application selects and admits exactly the atom and substrate solver
materials used by that run. The product Adapter verifies their exact native
names, samples them through the qualified product binding, and proposes one
task-scoped scientific material binding. That binding cannot be exported or
used by another solver. CST has no current code, material binding, placeholder
type, or registry entry.

At the brief boundary, the library may validate one explicitly proposed
canonical family and frame it as a user-confirmation question. It exposes no
alias, fuzzy match, ranking, or automatic substitution: only a confirmed family
may enter the immutable brief, and a question is neither advice nor evidence.

## External solver order

`configured → found → versioned → licensed → qualified → available`

The user supplies exact solver, API, and license-utility paths in
`.env.lumerical`; MetaCraft defines no general `.env` credential channel. The
project material library holds reviewed solver-material selections outside the
product environment file. Product qualification checks software identity,
licence, template mechanics, and capacity without pre-sampling a global
material set.
Before a ready material-binding task opens a native session, material
preflight reports every requested family that lacks one selected solver
material. An unrelated case or future aim cannot block that task merely
because its own materials are not registered.

A binding names what one exact qualified implementation can do. A positive current capacity names how many workers its scope may admit. A permit names which one worker may run. Binding carries no instantaneous parallel limit.

Qualification is immutable evidence, not permanent solver status. Capacity references matching qualification and fresh license and compute observations. `available` is derived from a matching binding and fresh positive capacity; it is not stored as a separate mutable object.

Local compute is shared across solver products. Python's workstation Module
forms fixed lanes of four distinct physical cores in one locality cell,
excludes SMT siblings, and contains one external process tree beneath a
16-GiB memory limit. A product-specific solver Adapter supplies its chosen
entrypoint and owns license facts, native construction, and observation
parsing. Lumerical currently starts direct `fdtd-engine.exe`; another product
may use an Adapter-owned API worker. Future CST or COMSOL code must reuse the
workstation Interface rather than duplicate placement policy.

Each active Lumerical lane may retain one hidden product session across its
candidate wave, but the workstation owns that session and every direct-engine
descendant for the lane's complete lifetime. The four-core, no-SMT, locality,
and 16-GiB rules apply to the whole tree; reuse is not an unplaced exception
and introduces no GUI concept.

The Lumerical Adapter records the native `lumerical_gui` and
`lumerical_solve` feature limits separately. Its admitted capacity is the
minimum of both feature pools and the workstation lane count; one feature is
never used as a proxy for the other.

Software discovery, API loading, license checkout, template construction, and
solver execution are distinct facts. A successful construction read-back does
not authorize execution. Until an engine run is verified, qualification stops
at `licensed` and emits neither a binding nor capacity. The current execution
fixture verifies propagation response and both geometric-response input bases;
one route cannot qualify the other.
