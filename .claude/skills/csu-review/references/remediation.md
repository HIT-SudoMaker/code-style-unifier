# Evidence-based remediation

Read this reference only for a repair or Project Fact registration request.
The parent SKILL.md owns capture and interpretation; use it for every fresh run.

## Repair source

Proceed only with source-repair authorization and evidence attributable to the
current target. Freeze executable, Authority bytes and scope; record the original
Seal, source revision or content identity, and selected Finding's rule, grade,
path, line, subject and observation. Obtain a current review when needed.
Missing source, signature or contract facts stop repair at an evidence request.
An unauthorized workaround does not authorize a different source change or rescan.

1. Fix the observed source contract while keeping the governed declaration visible.
2. Preserve native documentation ownership: Python suite-first triple-double-quoted
   docstring with standalone opening/closing quotes; Rust attached outer rustdoc;
   C/C++ adjacent controlled `/** ... */` attached to the native owner.
3. Retain meaningful internal summaries and signature-matched public contracts.
   Keep delimiters adjacent to identities, use minimal ASCII-space alignment within
   each field role, and retain the punctuation required by the reported contract.
   Ordinary comments cannot replace documentation or create directive exemptions.
4. Review the changed source with the frozen inputs into a new run. Identify the
   new source snapshot; the workspace CLI has no `--revision` option.
5. Explain each changed Finding or Blocked family. A missing Finding alone is not
   a repair: the declaration must remain reviewed and the required family complete.
   Distinguish a repaired item from an entirely Clean scope.

Unexpected new Findings, new Blocked families or input drift require investigation;
do not silently accept them, broaden the task, or revert unrelated user changes.
A parseability repair may expose previously blocked Findings: report that transition
honestly before planning further edits. Preserve the old result and Seal.

Changing Authority, lowering Grade, excluding source, hiding declarations, replacing
docstrings with ordinary comments, or changing test expectations to accept a defect
does not close a source repair. Rename or restructure only for the authorized semantic
need, not to remove the declaration from observation. ReviewRequired needs its Owner
question answered; it is not permission to guess a rename or whitelist a Candidate.

## Draft Project Facts

Draft only the exact Owner question carried by ReviewRequired or a missing-fact
Blocked result. A located setup rejection may identify a missing header fact;
preserve that rejection as the basis, not a fabricated source Finding.
For initial missing Authority, explain the required setup; do not manufacture
business facts or copy CSU's self Authority.

| Project Fact | Maximum purpose |
|---|---|
| `token_vocabulary` | Close an exact unknown token, not a Candidate or Hard |
| `quantity_concepts` | State the exact Concept/suffix table; no dimensional inference |
| `public_callables` | Complete C/C++ public ownership; never downgrade native publicness |
| `header_languages` | Select C or C++ for one exact ambiguous `.h` path |
| `external_fixed_identifiers` | Close unknown for an exact observed Rust function owner/spelling |
| `dependency_authority` | Complete origin or applicability of the fixed order, not custom order |

Return proposed rows in chat, with their evidence and unresolved truth questions.
Sort by fact field, Profile, declaration role, owner and spelling where applicable.
The Owner alone edits the target project's Authority; this workflow does not write
registration files. Candidate spellings remain Owner questions even if requested
as vocabulary. Facts cannot set Rules, Grades, prefixes, Candidate lists, Profile
contracts, presentation, family switches or directive exceptions.

## Re-enter after Owner calibration

An Owner-accepted fact change starts a fresh Authority compilation and review,
not a continuation under the old identity. Preserve both runs and explain the
change of applicability; an unrelated fact cannot erase an independently proved
Hard. Record the actual new identity without assuming a no-op or duplicate row
must change a semantic digest. CSU checks fact admission and effect limits, not
the truth of unobservable business intent. The Owner remains responsible for it.
